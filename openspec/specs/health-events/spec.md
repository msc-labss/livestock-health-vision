## Purpose

Defines the canonical health event that leaves the system, carrying phenotype, confidence, provenance and context, together with alert generation, bounded evidence retention and export to an external consumer.

## Requirements

### Requirement: Canonical versioned event schema
Health events SHALL conform to a versioned schema carrying at minimum: animal identity, event timestamp, observation window, phenotype values, confidence, contributing sensors, model identities, site and the schema version.

#### Scenario: Event omitting a required field is refused
- **WHEN** an event is constructed without an observation window
- **THEN** construction fails naming the missing field, and no event is emitted

#### Scenario: Schema version travels with the event
- **WHEN** an event is exported
- **THEN** the consumer can read the schema version from the event itself without out-of-band knowledge

### Requirement: Declared threshold policy
Alerts SHALL be generated by a named, versioned threshold policy, and each alert SHALL record the policy identity that produced it.

#### Scenario: Alert names the policy that raised it
- **WHEN** a risk score crosses a threshold and an alert is raised
- **THEN** the alert records the threshold policy identity and version

#### Scenario: Policy change is visible in the event stream
- **WHEN** the threshold policy is changed and comparable scores are reprocessed
- **THEN** alerts produced before and after are distinguishable by the recorded policy identity

### Requirement: Bounded evidence retention
An alert-level event SHALL retain a bounded evidence clip covering its observation window. Non-alert observations SHALL NOT retain clips.

#### Scenario: Alert retains a reviewable clip
- **WHEN** an alert is raised
- **THEN** a clip bounded by the configured duration around the observation window is retained and is retrievable from the event

#### Scenario: Routine observation retains no clip
- **WHEN** an observation does not raise an alert
- **THEN** no clip is retained for it

### Requirement: Human masking before retention
Any retained evidence clip SHALL have the configured human masking applied before it is written to storage.

#### Scenario: Masking is applied at write time
- **WHEN** an evidence clip is retained from footage containing a person
- **THEN** the stored clip has masking applied, and no unmasked copy is written to storage

#### Scenario: Masking failure blocks retention
- **WHEN** masking cannot be applied to a clip
- **THEN** the clip is not retained, and the event records that evidence retention failed

### Requirement: Export delivery contract
Events SHALL be exported to an external consumer with at-least-once delivery and an idempotency key, so that redelivery does not duplicate a health event downstream.

#### Scenario: Redelivered event is idempotent
- **WHEN** the same event is delivered twice because of a retry
- **THEN** the consumer can detect the duplicate from the idempotency key

#### Scenario: Export failure does not lose the event
- **WHEN** the external consumer is unavailable
- **THEN** the event is retained and retried, and the run reports the number of undelivered events

### Requirement: Stubbed inference is disclosed on the event
An event whose risk assessment derives from stubbed or injected inference SHALL be marked as such and SHALL NOT be presented as a clinical finding.

#### Scenario: Stub-derived event is marked
- **WHEN** an event is produced during P0 from the stubbed inference path
- **THEN** the event carries a marker identifying it as non-clinical and stub-derived
